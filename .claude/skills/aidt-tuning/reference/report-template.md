# チューニング状況レポートの構成

ユーザーから共有用やまとめの依頼があれば、Markdown ファイル (または Artifact) として作成する。
会話内の短い報告なら 1〜4 だけでよい。

```markdown
# <機体名> チューニング状況 (<日付>)

## 1. 現状サマリー (3 行以内)
- 例: ノイズは良好。プロップウォッシュがまだ残る。次は D を少し上げたい。

## 2. 最新フライトの評価
- ログ: <ファイル名> / 飛行 <秒> / データ品質 <score> (<不足があれば一言>)
- ノイズ: フィルター後 <値> deg/s、D-term <値>%、主なピーク <周波数 (種類)>
- 応答: roll オーバーシュート <値>% / 遅延 <値>ms、pitch …、yaw …
- 挙動: プロップウォッシュ比 <値>、高スロットル発振 <値>、飽和 <値>%

## 3. 前回からの変化
- 変更した設定: <name: old → new> (aidt history の applied_changes)
- 改善 / 悪化した指標: aidt compare の better/worse の主な行
- パイロットの体感: journal の feedback

## 4. 次の一手
- 提案する変更 (理由つき、小さく)
- 次の飛行でやってほしいこと (flight_plan の要約)

## 5. 経緯 (任意)
- journal の時系列を要約 (日付 / 変更 / 結果)
```

## 書き方の注意

- 数値は aidt の JSON からそのまま引用する。推測で補わない。
- 改善・悪化の判断は `compare` の verdict に基づく。同じ条件の飛行でない場合 (レースとテスト飛行を比べるときなど) はその旨を注記する。
- 専門用語には、初出時に短い説明を添える (例: 「プロップウォッシュ (急減速時のプロペラ乱流による揺れ)」)。
